Atropos 框架 两阶段训练 11 个 Parser 5 个 Benchmark 密封测试环境
核心命题：RL 训练基础设施是 Hermes 独有的工程基因。从 Atropos 环境定义 → HermesAgentLoop 异步执行 → Batch Runner 批量轨迹生成 → Benchmark 评估 → ~15,000 测试验证，Hermes 提供了完整的"可训练 Agent 框架"闭环。这是它与 Gemini CLI 和 Claude Code 作为"编程助手工具"定位的根本差异。
RL 训练基础设施
Atropos 框架 + HermesAgentLoop + Benchmark 环境
框架层 Atropos 集成 (atroposlib)
BaseEnv：所有 Hermes 环境的抽象基类，提供 setup/get_next_item/format_prompt/compute_reward/evaluate 六个接口
BaseEnvConfig：max_agent_turns（30）、distribution（工具集分布）、terminal_backend、tool_pool_size（128）
执行层 HermesAgentLoop (agent_loop.py)
vs AIAgent：async for 循环（非同步 while）、ThreadPoolExecutor 工具执行（128 workers）、AgentResult 轻量结果
死锁防护：工具通过 ThreadPoolExecutor 异步执行，避免 Modal/Docker/Daytona 的 asyncio.run() 与 Atropos 事件循环冲突

两阶段训练模式
Phase 1 (API Server) + Phase 2 (ManagedServer + Tool Parser)
Phase 1 OpenAI Server 模式
直接连接 OpenAI-compatible API（VLLM、SGLang、OpenRouter）。模型通过标准 tool_calls 交互，无需自定义 parser。适用于快速迭代和成熟 API 服务。
Phase 2 ManagedServer 模式
使用 Atropos 的 ManagedServer + 客户端 tool call parser。支持需要自定义解析的模型（GLM 的中文 function call、DeepSeek 的特殊 JSON 结构、Kimi 的 Moonshot 格式）。

关键设计 skip_context_files=True
每个 worker 创建 AIAgent(skip_context_files=True)，不加载用户的 MEMORY.md/USER.md。这确保轨迹干净——反映模型的原始能力，不被用户特定上下文污染。
Checkpoint 内容级断点恢复
--resume 标志触发 _scan_completed_prompts_by_content()——通过匹配 prompt 文本内容（而非行号）判断哪些已完成。即使数据集顺序变化，也能正确恢复。
输出 轨迹格式
每条轨迹 JSON 包含：prompt + messages（from/value pairs）+ tool_stats（61 工具调用/成功/失败计数）+ reasoning_stats + turns_used + finished_naturally
