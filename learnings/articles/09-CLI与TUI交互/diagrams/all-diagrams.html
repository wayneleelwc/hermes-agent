核心命题：Hermes 同时提供 CLI（prompt_toolkit）和 TUI（Ink React）两种界面，两者共享同一个 AIAgent 内核。差异仅在 I/O 层——CLI 直接调用内核方法，TUI 通过 tui_gateway 的 JSON-RPC 桥接。皮肤引擎让终端体验高度可定制。

TUI JSON-RPC 通信架构
Ink React 前端通过 tui_gateway 桥接 Python 后端
前端 Ink React 组件树
ui-tui/src/ 是 TypeScript Ink React 应用。组件包括：消息列表渲染、输入框、Spinner 动画、工具调用展示、设置面板等。通过 JSON-RPC 协议与 Python 后端通信。
通信桥 tui_gateway JSON-RPC
tui_gateway/ 是 Python JSON-RPC 服务端，跑在 stdio 上：
① 接收前端 JSON-RPC 请求 → ② 转换为 AIAgent 方法调用 → ③ 流式返回结果（yield JSON chunks）→ ④ 前端 React 组件实时更新
进程模型 三进程架构
TUI React 进程（Node.js）← stdio pipe → tui_gateway 进程（Python）← 对象引用 → AIAgent（同进程）。三个层次、两个进程、一个内核。

派生 命令注册表架构
COMMAND_REGISTRY 是中央注册表，每个命令注册时指定：触发词、处理函数、帮助文本、自动补全列表。CLI 和 TUI 共享同一注册表——TUI 模式通过 JSON-RPC 远程调用同一组命令处理函数。

关键差异：Hermes 是唯一同时提供 CLI 和 TUI 两种界面的系统，也是唯一有皮肤引擎的系统。这种"双界面"设计源于 Hermes 的多入口架构——Gateway 不需要界面，CLI 需要高效 REPL，TUI 需要丰富可视化。三种场景各取所需。
