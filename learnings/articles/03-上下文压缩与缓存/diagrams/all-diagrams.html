核心命题：压缩不是"丢弃消息"，而是"在有限的 token 预算内保留最多的有用信息"。8 字段结构化模板确保关键信息不丢失，迭代摘要更新确保跨压缩的信息连续性。

级别策略触发条件cooldown

错误类型分化：permanent 错误（模型不存在）立即 fallback，transient 错误（超时/限流）做 cooldown。不同错误走不同路径，避免在不可恢复的错误上浪费重试。

TTL 两种缓存期限
5m：写入成本 1.25x，适合短会话。1h：写入成本 2x，适合长会话（暂停 >5 分钟后仍命中）。
失效 压缩触发重建
压缩改变 system prompt 和消息列表 → cache prefix 不再匹配 → 下次 API 调用建立新缓存。Session DB 中的 system_prompt 被更新以保证后续轮次的缓存一致性。
