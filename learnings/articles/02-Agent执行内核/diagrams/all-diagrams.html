同步循环 双层预算 线程中断 按类型重试 体面告别
核心命题：Hermes 用一条朴素的 while 循环驱动整个 Agent 行为。同步模型不等于功能受限——流式输出走 callback、中断走线程信号、子 Agent 走新实例、预算走共享对象。关键在于在循环的固定边界点上插入非同步操作，而不是把整个循环变成异步的。

循环条件 while 三重判定
while (api_call_count < max_iterations AND budget.remaining > 0) OR _budget_grace_call
① 硬上限（本地 90 / 子 Agent 50）② 共享预算池 ③ 体面告别机会
消息流 二层模型
messages（持久化）→ api_messages（API 调用副本）：注入 memory context、复制 reasoning、清理内部字段、JSON 规范化、trim whitespace。原始消息不修改。
退出码 _turn_exit_reason
循环结束时记录 _turn_exit_reason：interrupted_by_user / budget_exhausted / max_iterations_reached / completed / unknown
双层预算体系
max_iterations（硬上限）+ IterationBudget（共享池）
第一层 本地上限 max_iterations
默认值：父 Agent 90 / 子 Agent 50
作用：防止单个 Agent 无限循环
检查时机：每轮循环开始时，api_call_count < max_iterations
第二层 共享预算 IterationBudget
实例共享：父 Agent 创建 IterationBudget 实例 → 子 Agent 在 delegation 时继承同一个实例
消费逻辑：budget.consume() → 原子递减 remaining → 返回 False 时触发体面告别
关键价值：子 Agent 不会绕过总预算限制
预算耗尽 体面告别流程
① 注入预算耗尽警告消息（user role）→ ② 设置 _budget_grace_call = True → ③ 允许最后一次 API 调用 → ④ 如果返回 tool_call → 循环自然退出 → ⑤ 强制生成摘要
设计洞察：Hermes 只在预算真正耗尽时才通知模型，中间不做压力提示。原因是"intermediate pressure warnings caused models to give up prematurely on complex tasks (#7915)"。

对比 interrupt vs steer
interrupt()：立即设置标志位 + 线程信号 → Agent 在下次循环检查时 break → 用中断消息启动新一轮 run_conversation()
steer()：不设置标志位 → 等待当前工具批次完成 → 将指引文本追加到最后一个 tool 消息的 content → 模型下一次迭代自然看到

容错哲学：每个错误类型都有独立的 retry 计数器和处理策略，互不干扰。Fallback provider 切换是"核选项"——一旦激活，所有后续轮次都使用 fallback，直到下一次 run_conversation() 恢复主 provider。

架构选择：Python 生态天然偏向同步模型——while 循环比 async generator 更容易调试，多线程信号比 asyncio 事件更容易跨平台。Hermes 把异步能力（流式输出、中断、子 Agent）都嫁接在同步循环的固定边界点上，而非把整个循环变成异步。这是一种务实的工程选择。
