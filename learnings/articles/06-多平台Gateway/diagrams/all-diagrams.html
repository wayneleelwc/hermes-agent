核心命题：Gateway 是 Hermes 独有的架构基因——一个 asyncio 长驻进程同时服务 20 个消息平台。所有平台适配器实现相同的 on_message() + send_message() 接口，将异构平台的消息统一注入到同一个 AIAgent 内核。

内核 GatewayRunner — 统一消息分发引擎
GatewayRunner 是 gateway/run.py 的核心类，负责：
① 启动时遍历所有已配置平台 → adapter.start() 建立连接
② 运行时收到事件 → _handle_message() → 鉴权 → 会话加载 → AIAgent
③ 回复通过 adapter.send_message() 投递回原平台
并发 asyncio.to_thread() 线程池
多个平台的消息并行触发 _handle_message()。每个消息处理在独立 asyncio task 中运行，但 AIAgent 是同步的，实际执行通过 asyncio.to_thread() 转移到线程池，避免阻塞事件循环。

接口契约 PlatformAdapter 抽象
所有平台适配器实现统一接口：start() 建立连接、on_message() 接收消息回调、send_message() 投递回复。GatewayRunner 不关心底层协议差异——只要适配器遵守契约，就能无缝接入。

Session Key 多维度会话隔离
Key 格式：agent:<profile>:<platform>:<chat_type>:<chat_id>
确保不同 profile、不同平台、群聊 vs 私聊的会话完全隔离。同一用户在不同平台上的对话互不干扰。
Cron 定时任务调度器
Gateway 内置 cron/ 调度器：用户通过 skill 创建定时任务 → jobs.json 持久化 → scheduler 定期检查 → 触发时 fork 新 AIAgent 执行。Curator 的 7 天审查周期也由此驱动。
Hook 生命周期钩子系统
on_session_start / pre_llm_call / pre_api_request / agent:step — 四个钩子覆盖 Agent 完整生命周期，支持插件在关键节点注入自定义逻辑。
