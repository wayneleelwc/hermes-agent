核心命题：Hermes 的多入口架构证明，Agent 系统的内核逻辑（Prompt 组装、Provider 路由、工具分发、上下文压缩、记忆管理、会话持久化）与 I/O 适配层（CLI/Gateway/ACP/Batch/API）可以完全解耦。五个入口共享同一个 AIAgent 实例，差异仅在于输入来源和输出方向的适配。

关键 Platform Adapter 模式
每个消息平台实现 on_message() + send_message() 接口 → 启动时建立 WebSocket/长轮询/Webhook → 收到消息后创建 AIAgent 实例 → run_conversation() → 通过 adapter 返回消息
关键 会话保持
gateway/session.py 的 SessionStore 维护跨会话的对话历史。每个平台用户有独立的 session key（如 agent:main:telegram:dm:123），确保多用户并发时历史不会混淆。
关键 Cron 集成
Gateway 内置 cron/ 调度器。定时任务和 Curator（自主知识管家）扫描由 cron ticker 触发，复用 Gateway 的 AIAgent 创建流程。

设计启示：五个入口不是五个独立的应用，而是同一个 AIAgent 的五种 I/O 适配方式。CLI 适配 stdin/stdout，Gateway 适配消息事件/平台回复，ACP 适配 JSON-RPC stdio，Batch Runner 适配文件 I/O，API Server 适配 HTTP。新增第六个入口只需实现新的 I/O 适配层，无需修改内核。

覆盖语义：四层配置没有"合并"语义，只有"覆盖"语义。后一层总是替换前一层的同名字段。这种设计避免了多层配置合并带来的歧义性——任何时候，最终生效的值都可以通过追踪到最具体的层级来唯一确定。
