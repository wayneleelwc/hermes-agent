核心命题：Hermes 的子 Agent 运行在独立线程中，但共享父 Agent 的 IterationBudget 实例。这意味着子 Agent 的工作也是总工作的一部分——不能绕过预算限制。这是 Hermes 子 Agent 系统最独特的设计选择。
多 Agent 并行架构
delegate_task（线程隔离）+ Batch Runner（进程隔离）两种并行模式
delegate_task 任务委派模式
场景：父 Agent 将复杂子任务委派给子 Agent 独立完成
隔离：子 Agent 在独立线程中运行（共享进程空间）
预算：继承父 Agent 的 IterationBudget 实例（共享池）
中断：父 Agent 中断时递归传播到所有活跃子 Agent
限制：子 Agent 默认 max_iterations=50（父=90）
安全：子 Agent 默认 auto-deny 危险命令
Batch Runner 批量轨迹生成模式
场景：大规模并行生成训练/评估轨迹
隔离：每个 worker 是独立进程（multiprocessing.Pool）
预算：各 worker 独立预算，互不影响
特点：skip_context_files=True（避免污染轨迹）、checkpoint 支持 resume
用途：RL 训练数据生成、批量评估

安全约束 子 Agent 的 5 层隔离
① 线程隔离：独立线程运行，崩溃不影响父 Agent
② 预算隔离：共享预算池，不能绕过总限制
③ 中断传播：父中断 → 递归传播到所有子 Agent
④ 工具限制：max_iterations=50（父=90）
⑤ 审批安全：默认 auto-deny 危险命令

架构选择：Hermes 选择线程级隔离而非进程级，核心原因是共享预算。共享预算使整体成本可控——父 Agent 和所有子 Agent 从同一个池子消费。大多数系统给子 Agent 独立预算，但 Hermes 认为子 Agent 的工作也是总工作的一部分。这个设计在"控制力"和"隔离性"之间做了一个清晰的取舍。
